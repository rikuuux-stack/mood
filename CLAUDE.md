## Le projet
**Nom du site : Mood.** Moodboard en ligne participatif : les visiteurs déposent une image ou un texte ; rien n'est visible avant validation de l'administrateur. **Adresse : https://moodwall.pages.dev** (Cloudflare Pages, projet « moodwall », branche `main`, sans build, dossier racine). Dépôt public `rikuuux-stack/mood` (anciennement `riku-portfolio`, renommé ; GitHub Pages désactivé). L'auteur du site n'est pas développeur : expliquer en français, simplement, pas à pas.
- **Aucun nom de personne sur le site** (demande de l'auteur) : ni « RIKU », ni nom civil, nulle part (onglet, meta, messages, libellés, admin, à propos, commentaires des fichiers servis, README/docs, ce fichier — Cloudflare Pages sert tout le dépôt). Seule exception : l'adresse de contact rikuuux@gmail.com pour les demandes de retrait (obligation d'hébergeur). Dans le code et la base, la marque des dépôts de l'administrateur s'appelle `is_author` (ancien nom de colonne retiré en deux étapes : migrations `20261013120000_is_author.sql` puis `20261013130000_is_author_cleanup.sql`, qui supprime l'ancienne colonne ; les anciens fichiers de migration, déjà appliqués, gardent l'ancien nom et ne se réécrivent pas).

Appliqué à l'affichage, les fichiers restent intacts.

IBM Plex Sans JP ExtraLight (200) pour tous les textes, Thin (100) pour « Mood », IBM Plex Mono ExtraLight pour les légendes ; bordures et filets à 1 px. Aucun gras. Under review. », « Leave a trace… », « No posts yet. Start the wall. », « Under review », « This month: … ». **Les messages d'erreur restent traduits FR/JA/EN**, ainsi que les mentions légales (inchangées) et les libellés invisibles des lecteurs d'écran. Pas de pied de page, pas de pseudo sur le mur (seulement à l'agrandissement). Langue détectée d'après le navigateur. Ne rien rajouter à l'écran sans demander à l'auteur.

Fond + grain = couche fixe `body::before` (hauteur `100lvh`), jamais `100vh` ni `background-attachment: fixed`. Ses dépôts depuis /admin/ restent publiés directement ; « me » n'apparaît que dans /admin/.
- **Un dépôt = une image, des mots, ou les deux** (un seul formulaire, sans onglets). **Pixels contre mots** (`js/budget.js`, règle à reprendre telle quelle côté serveur) : caractères autorisés = 500 × (1 − pixels / 4 000 000), arrondi, minimum 40 ; sans image 500. Pixels = taille publiée (après réduction à 2000 px). Le commentaire s'affiche sous la photo.
- **Mur** : chevauchement des images max **18 % (8 % sur mobile)** ; un texte ne chevauche RIEN (ni texte, ni image) et garde un espace libre autour de lui (24 px, 28 px sur mobile) ; le commentaire sous une photo n'est jamais recouvert ; **le plus récent toujours au-dessus** ; **un toucher / clic ouvre directement l'agrandissement** (précédent / suivant : boutons ‹ ›, balayage, flèches) ; ordinateur : au survol / focus l'élément passe au-dessus, monte de 6 px, scale 1,015, 140 ms (son âge ne change pas) ; mobile : retour scale .985 ≈ 80 ms puis ouverture. Cadres aux bonnes proportions affichés avant les images, fondu 220 ms. **Tout le mur, sans bouton « More »** : les informations (textes, tailles, dates) sont lues par paquets de 500 (`CONFIG.wall.batch`) en arrière-plan ; chaque image n'est téléchargée qu'à l'approche de l'écran (IntersectionObserver `near`, un écran de marge, `watch()` dans `js/main.js`) et **libérée au-delà de 3 écrans** (`far` : `src` retiré, redemandé au cache au retour) ; le cadre garde toujours sa taille (la composition ne bouge pas). Mémoire : ≈ 30 images au plus à la fois, quelle que soit la taille du mur. Miniatures actuelles : 800 px de grand côté (≈ 1,6 Mo décodée). Bouton Wall / List (choix mémorisé). Règles testées par `node tests/wall.test.mjs`.
- **Fuseau de référence du mur : Asia/Tokyo** (décision de l'auteur) : le mur est identique pour tous les visiteurs, quel que soit leur pays. Tout ce qui dépend du mois sur le mur (strates, filets, strate en cours) se calcule à l'heure de Tokyo (`wallMonth` dans `js/wall.js`, UTC + 9 h, pas d'heure d'été). Seule exception : la date en bas d'un fragment « Keep » est la date du téléphone du visiteur.
- **Mur IMMOBILE** (décision de l'auteur) : plus aucune dérive ni réaction au doigt / à l'inclinaison (#11 fermée). **C'est le TEMPS qui transforme le mur** (`js/wall.js`) :
  - **Érosion**, courbe « Saison » : visibilité v = 1 jusqu'à 7 jours après la validation, puis 0,3 + 0,7·e^(−(j−7)/41) (≈ 70 % à 30 j, ≈ 39 % à 90 j, plancher 30 %). **Images : les pixels CLAIRS deviennent transparents avec l'âge** (décision de l'auteur) : on voit à travers les images du dessous et le fond ; à la fin, il ne reste que les parties sombres ; grain un peu plus fort. **4 paliers fixes** (`stageOf` dans `js/wall.js` : neuve < 10 j, palier 1 ≈ 10 j, 2 ≈ 22 j, 3 ≈ 40 j, 4 ≈ 73 j → classes `.age-1` … `.age-4`) → 4 filtres SVG partagés `#erode1` … `#erode4` dans `index.html` (N&B + courbe, grain, alpha = 1 − pente × (gris − seuil)) : rien de calculé image par image. Jamais d'opacité sur le dépôt. Pas de retour à neuf au survol : seulement à l'ouverture en grand. Textes et commentaires : à peine adoucis (≥ 10:1). Uniquement à l'affichage, fichiers intacts. **Après 180 jours, le dépôt quitte le mur** et ne vit plus que dans la vue List (archive, intacte).
  - **Strates** : le mur se lit de haut en bas par couches (mois dans le **fuseau de référence du mur : Asia/Tokyo**, le même pour tous les visiteurs — jamais l'heure du téléphone ni l'UTC —, + consigne gardée sur chaque dépôt, `strataKey` / `wallMonth`) ; un filet fin et le mot de la consigne séparent les strates ; un mois sans consigne : le filet seul. Pas de dates ni de compteurs sur le mur.
  - **Consigne du mois** : un court texte anglais (≤ 60 car.) réglé dans /admin/ (champ « Prompt »), table `prompt` (une ligne), vue publique `current_prompt`, gardée sur chaque dépôt (`posts.prompt`) ; affichée « This month: … » sous le bandeau et dans Drop.
- **Vitesse perçue** : le premier paquet du mur (500 dépôts au plus, et la consigne) est gardé dans `localStorage` (`mood-wall-v2`, ignorée au-delà de 24 h) et s'affiche tout de suite, puis la version à jour arrive en arrière-plan (glissement vers les nouvelles places, retirés effacés). Éléments réutilisés d'un rendu à l'autre (`nodeCache`), placement progressif strate par strate (`createLayout`, options `top` / `first`), préchargement des 14 premières miniatures, `preconnect` vers Supabase. Fichiers publiés envoyés avec `cacheControl` d'un an (`CACHE` dans `_shared/http.js`, noms uniques). Supabase reste à Mumbai (visiteurs entre le Japon et la France).
- **Keep — fragment du mur** (`js/fragment.js`, chargé seulement au premier « Keep ») : dans l'agrandissement d'un dépôt placé sur le mur (pas en vue List, pas « en attente »), « Keep » → format 4:5 (1080×1350, défaut) ou 9:16 (1080×1920) → l'image est fabriquée sur l'appareil (aperçu), puis « Share » (iPhone / Android : `navigator.share` avec le fichier) ou « Save » (téléchargement). Deux temps car le partage exige un geste récent. Contenu : le dépôt au centre (≈ 42 % du cadre), ses voisins tels qu'ils sont placés et empilés, coupés par le bord ; fond + grain ; l'érosion RÉELLE de chacun refaite en pixels avec les mêmes valeurs que l'écran (`TONE`, `ERODE` dans `js/wall.js`, égalité avec `index.html` vérifiée par `tests/wall.test.mjs`) ; textes avec la même police ; filets des strates sans leur mot ; dépôts « en attente » exclus ; en bas une seule ligne IBM Plex Mono « moodwall.pages.dev — JJ.MM.AAAA — consigne » (date LOCALE du téléphone du visiteur, elle : à Paris le 30.09 à 17 h 30 → « 30.09.2026 », même si c'est déjà le 1er octobre à Tokyo ; testé avec `timezoneId` Tokyo / Paris / Los Angeles). Aucun nom. JPEG sans métadonnées (`stripMetadata`). Toutes les images du site sont chargées avec `crossOrigin="anonymous"` (le canvas reste lisible) : Supabase Storage doit renvoyer `Access-Control-Allow-Origin` (vérifié par `tests/e2e.mjs`). Mention traduite `mentionsKeep` dans le panneau Mood.
- **Mon dépôt en attente** : après l'envoi, `submit` renvoie l'`id` ; le navigateur du visiteur garde une copie (texte + miniature ≈ 400 px en data URL) dans `localStorage` (`mood-pending-v1`) et l'affiche sur SON mur, pâle, « Under review », jusqu'à ce que l'id apparaisse dans le mur public (copie retirée) ou au plus 14 jours. Personne d'autre ne la voit ; elle ne se signale pas.
- **Taille S / M / L** (M par défaut), choisie au dépôt, pour les images ET les textes (ordinateur : 75 / 100 / 135 % de ≈ 1/6 de la largeur ; iPhone : 35 / 50 / 70 % ; textes : 12/14/16 px, 13/14/15 sur mobile ; ±8 % de variation). Colonne `posts.size` (check s/m/l), exposée par la vue `wall`, revérifiée par `submit` (erreur `display`), modifiable dans l'admin (`moderate` action `resize`, tout statut).
- **Pas de grain réglable** (décision de l'auteur) : le grain est une règle globale du site (`.photo::after`), rien n'est incrusté dans les images (`renderImage` garde un paramètre `grain`, laissé à 0).
- **Vidéos et GIF perso** (remplacent le plan de la #12, fermée) : dépôt d'une vidéo (galerie ou caméra) ou d'un GIF animé (un GIF d'une seule image est une photo). **Tout est converti sur l'appareil** (`js/video.js`, chargé au choix du fichier) : MP4 H.264, 480 px de grand côté, ≤ 24 i/s, ≈ 300 kb/s à débit constant (≈ 2,2 Mo pour 60 s ; si le fichier dépasse quand même 4 Mo, jusqu'à deux passes de plus à débit réduit et 12 puis 8 i/s), **noir et blanc ET courbe de tons intégrés dans le fichier** (aucun filtre à la lecture), sans son, sans métadonnées (`tags: {}`, images redessinées), 60 s au plus. Curseur « Start » (avec aperçu) pour TOUTES les vidéos : l'image sous le curseur devient l'image fixe (poster, 800 px, en couleur, traitée à l'affichage comme une photo) et la vidéo commence là ; par défaut ≈ 1 s. GIF : première image, sans curseur, joué en boucle. Pas de grain incrusté (grain global du site). Pendant la conversion : barre de progression, « Keep this screen open » (FR/JA/EN), Cancel. Trois chemins : WebCodecs (Mediabunny, rapide) → sinon lecture par `<video>` + WebCodecs (temps réel) → sinon MediaRecorder MP4 (iOS < 16.4) → sinon refus clair (`eVideoBrowser`) ; vidéo impossible à lire (HEVC/HDR/4K non pris en charge) → `eVideoUnsupported`. Bibliothèques copiées dans `js/vendor/` : **Mediabunny** (MPL-2.0, seule option maintenue — mp4-muxer est abandonné au profit de Mediabunny ; 691 Ko, ≈ 175 Ko compressé, chargé seulement au choix d'une vidéo) et **omggif** (MIT ; Safari ne décode pas les GIF image par image). Mediabunny crée de petits outils internes en `blob:` → CSP `worker-src 'self' blob:` ; lecture des vidéos → `media-src`.
  - **Affichage** : sur le mur et dans la liste, l'image fixe + un petit ▶ discret (`.vmark`), même érosion que les photos, la vidéo n'est JAMAIS téléchargée avant l'ouverture ; dans l'agrandissement, la vidéo se télécharge et joue muette, en boucle, neuve ; « Réduire les animations » → pas de lecture automatique, un bouton ▶ ; arrêtée et libérée (`freeVideos`) à la fermeture ou au passage à un autre dépôt. Keep : l'image fixe érodée.
  - **Serveur** : `kind = 'video'`, `image_path` = la vidéo MP4, `thumb_path` = l'image fixe, `duration` (≤ 60,5 s). `submit` lit la vidéo de l'intérieur (`_shared/mp4.js`, copie `js/mp4.js`) : H.264, une piste, pas de son, pas de GPS, ≤ 480 px, ≤ 60,5 s, ≤ 4 Mo ; mêmes limites et même modération que les photos. **Plafond de stockage** : nouvelles vidéos refusées si le total dépasse 900 Mo (`full` → « Wall full — come back later. »), avertissement dans /admin/ dès 700 Mo. /admin/ montre et lit la vidéo avant validation (et son poids réel).

Refus seulement si illisible (`eDecode`) ou énorme (> 60 Mo ou > 100 mégapixels : `eHuge`, limite de mémoire sûre sur iPhone). Plus aucune mention de formats dans le formulaire.

## Serveur (Supabase)
- `supabase/migrations/` : tables `posts`, `reports`, `admins` en RLS **sans aucune politique** + droits retirés à anon/authenticated ; la seule lecture publique est la vue `wall` (dépôts `approved`, sans IP/statut/signalements). Buckets : `pending` privé, `published` public en lecture. 3 signalements → `hidden` (déclencheur). Le compte rikuuux@gmail.com devient admin automatiquement (déclencheur sur auth.users).
- `supabase/functions/` (Deno, `.js`) : `submit` (contrôles gratuits → captcha → limite 3/h 10/j par IP hachée → fichiers dans `pending` → ligne `pending` → e-mail Resend), `report`, `moderate` (admin : liste, approve = déplacement pending→published, reject, remove, restore). L'administrateur connecté peut déposer via `submit` : publié directement, `is_author`.
- **Envoi d'image** : Safari (iPhone) n'encode pas le WebP et ajoute un bloc Exif à ses JPEG → `js/image.js` retire lui-même les métadonnées (`stripMetadata`) avant le contrôle. Une image choisie mais refusée bloque l'envoi (jamais de texte seul « à la place ») ; bouton désactivé pendant la préparation et l'envoi (pas de double dépôt). Côté serveur, un champ `image` vide/illisible est refusé (`type`), et `submit` renvoie `kind`.
- `supabase/functions/_shared/budget.js` est une COPIE de `js/budget.js` (`tests/server.test.mjs` vérifie l'égalité).
- Déploiement : `.github/workflows/supabase.yml` (push sur main touchant `supabase/`, ou « Run workflow ») puis `tests/e2e.mjs` contre le vrai projet ; chaque lundi, e2e seul (garde le projet actif). Secrets GitHub : `SUPABASE_ACCESS_TOKEN`, `SUPABASE_DB_PASSWORD`. Secrets Supabase (Edge Functions ▸ Secrets) : `TURNSTILE_SECRET`, `RESEND_API_KEY` (facultatif).
- **Droits `service_role`** : sur ce projet, « Automatically expose new tables » est désactivé → une nouvelle table n'a AUCUN droit, même pour `service_role` (incident : connexion admin refusée en 401 « admin »). Toute nouvelle table doit recevoir explicitement `grant … to service_role` dans sa migration (cf. `20261009200000_service_role_grants.sql`). Contrôle public sans données : `GET /functions/v1/moderate?health` (testé par `tests/e2e.mjs`).

## Cache-busting (obligatoire avant chaque mise en ligne)
- Toutes les adresses internes portent une empreinte du contenu : `js/main.js?v=…`, imports `./x.js?v=…` (statiques et `import()`), CSS, polices. Un fichier modifié change d'adresse, donc aucun visiteur ne garde une ancienne version en cache (incident réel : l'ancien `js/main.js` de l'expo 3D restait en cache et bloquait Mood).
- **Après toute modification de `index.html`, `css/` ou `js/` : `python3 tools/stamp.py`** (`tools/fonts/subset.py` le lance aussi). Un nouvel import doit être écrit avec un chemin relatif `./…` ; le script ajoute l'empreinte.
- Vérification : `python3 tools/stamp.py --check` (aussi lancée par GitHub Actions, `.github/workflows/checks.yml`).
- Limite : `index.html` lui-même ne peut pas porter d'empreinte (Cloudflare Pages le revalide à chaque visite).

## Hébergement (Cloudflare Pages)
- `_headers` est appliqué par Cloudflare Pages : CSP (site, Supabase `ovvdtthnykqvgarrjina.supabase.co`, Turnstile `challenges.cloudflare.com`, `blob:`/`data:` pour les images), cache long `immutable` pour `/js/*`, `/css/*`, `/assets/*` (sûr uniquement parce que toute adresse interne porte `?v=` — `stamp.py --check`), `/admin/*` en `noindex` + `no-store`. Nouveau domaine externe (script, image, API) → l'ajouter à la CSP, sinon il est bloqué.
- CORS des fonctions (`_shared/http.js`) : `moodwall.pages.dev` et ses aperçus `<id>.moodwall.pages.dev`, plus localhost (l'ancienne adresse `rikuuux-stack.github.io` est refusée, testé par e2e). Le widget Turnstile doit lister les mêmes hostnames.
- Tout le dépôt est servi publiquement (README, docs, CLAUDE.md, tests) : aucun secret, aucun nom de personne.
